# 작업 중 확인할 점

## 테스트 씬의 컴파일 오류가 게임 코드까지 막히는 경우

`Test.cs`와 `GameSessionChecks.cs`가 런타임 스크립트와 함께 `Assembly-CSharp`에 들어간다. `Test.unity`가 빌드 씬에 없어도 테스트의 오래된 필드나 메서드 이름이 컴파일을 막을 수 있다. 모델을 고칠 때는 `GameSessionChecks.cs`의 생성자 명명 인자와 `TestSessionData.cs`의 진행 데이터 참조도 확인한다.

## 씬을 열었는데 카드 화면이 안 나오는 경우

`SampleScene.unity`는 빌드 목록에서 `GameManager`와 카드 CSV를 사용해 세션을 시작한다. 프론트 카드 화면은 해당 씬에 연결이 필요하다. 개발용 화면을 확인하려면 `Assets/JMS/Scenes/Test.unity`를 직접 연다. 이 씬의 버튼은 임시 세션에서 동작한다.

## 저장 재현 중 일반 세이브가 바뀌는 경우

`GameManager`는 기본 사용자 데이터 경로에서 저장을 열고, 개발용 테스트는 임시 경로를 사용한다. 테스트 씬에서 매니저를 켜면 두 경로가 함께 동작할 수 있다. `Test Environment`에서 매니저가 꺼져 있는지 확인하고, 화면에 표시되는 저장 경로가 임시 디렉터리인지 확인한다.

구형 JSON이나 손상 JSON을 직접 만드는 검사는 파일을 쓰기 전에 검사 전용 임시 디렉터리를 생성한다. 정상 저장은 저장소가 디렉터리를 만들지만, 원시 JSON을 쓰는 검사는 저장소를 거치지 않는다.

## CSV 카드 변형의 결과가 예상과 다른 경우

변형 ID로 대사를 확인하고 사건 ID로 중복을 확인한다. 두 값을 혼용하면 다른 유산 분기의 변형이 같은 회차에 다시 나올 수 있다. `K-M01`에서 두 유산 플래그로 시작해 각각의 변형을 확인하면 이 차이를 검증할 수 있다.
