# 진행 상태

2026-11-12 기준 `JMS` 작업 트리에서 Unity 스크립트 컴파일과 `Assets/JMS/Scenes/Test.unity`의 자동 검사 22건을 확인했다. 실제 씬의 `GameManager`·CSV 참조와 임시 저장을 사용한 게임 진입점도 검증했다.

## 구현한 기능

- CSV에는 계층 5개, 사건 20개, 카드 변형 36종이 있다. 현재 행의 사건 유형은 모두 `main`이다.
- 새 게임은 첫 카드와 체크포인트를 저장하고 시작한다. 세션은 계층별 턴 한도, 메인 사건 순서와 예약, 유산 변형, 카드 소진에 따른 전환을 처리한다.
- 스탯 0 또는 100에서 체크포인트로 복귀한다. 저장에 성공한 계층 전환은 `CurrentCardChanged` 이후 `CasteChanged`로 알린다.
- 버전 1 저장은 카드 변형 ID와 턴 상태를 저장한다. 구형 카드 객체를 읽고, 손상 파일은 새 게임 저장으로 교체한다.
- 개발용 테스트 씬에서 턴 0·2·12, 랜덤 후보의 계층·현재 플래그·사건 중복 필터, 계층 조기 전환, 양쪽 유산 분기, 새 게임 저장과 실패 복구, 게임 오버 복귀, 구형·손상 저장을 포함한 자동 검사 22건이 통과했다. 일반 카드 추첨은 테스트용 CSV에서 확인했다.
- `SampleScene.unity`의 `GameManager`에서 새 게임, 이어하기, 선택, 복원을 호출할 수 있다. 수동 테스트도 같은 새 게임과 복원 경로를 사용하며 테스트용 저장을 별도로 둔다.
- 개발용 테스트 씬의 수동 화면은 세션의 현재 카드에 맞춰 카드 ID, 제목, 화자, 대사와 좌우 선택지를 표시한다. 플레이 모드에서 선택, 이어하기, 체크포인트 복원, 저장 실패, 카드가 비었을 때의 표시와 버튼 상태를 확인했다.
- `origin/JSW`에서 별도로 스와이프와 카드 화면 시제품을 확인했다. `JMS` 작업 트리에서는 해당 코드를 실행하는 씬이 없다.

## 남은 작업

1. 프론트가 만든 UI에 좌우 선택 진입점과 카드·계층 변경 알림을 연결한다. 스와이프 한 번이 선택 한 번으로 이어지는지 두 담당 영역을 함께 검증한다.
2. 엔딩 플래그의 최종 판정과 표시 규칙을 확인한다.
