# 저장소 작업 규칙

## 빌드, 검사, 릴리스

- 빌드는 사용자가 명시적으로 요청한 경우에만 실행한다.
- 변경 범위에서 실패한 검사는 원인을 고친 뒤 다시 확인한다. 실행한 검증과 소스만 읽어 확인한 결과를 구별한다. 작업 중 실행한 테스트 프로세스는 턴을 마치기 전에 종료한다.
- 화면 조작 도구는 다른 방법으로 필요한 확인을 할 수 없을 때 사용한다.
- 릴리스에 배포한 경우 이전 빌드본을 삭제한다. 배포 기록이나 게임 저장 파일은 빌드본과 구분한다.

## 파일과 의존성

- 수정하는 파일의 기존 문자 인코딩을 유지한다. 한글이 넓은 범위에서 깨져 보인다는 이유로 여러 파일을 일괄 변환하지 않는다.
- Unity 패키지 변경은 `Packages/manifest.json`과 잠금 파일을 기준으로 확인한다. 카드 파서의 NuGet 의존성은 `Assets/packages.config`를 기준으로 확인한다.
- 씬과 스크립트, CSV의 연결을 바꿀 때는 Unity `.meta`의 GUID와 씬의 직렬화된 참조를 함께 확인한다.
- 플레이 결과를 변경하는 진입점은 세션에 둔다. UI에 입력이나 화면을 연결할 때는 한 번의 확정 입력이 한 번만 세션에 전달되고, 화면이 그 세션의 결과를 표시하는지 확인한다. 검증에는 임시 저장 경로를 사용한다.
