# 게임 구성

동아리에서 만드는 Unity 2D 카드 게임이다. 현재 작업 브랜치인 `JMS`에서 계층별 사건 데이터, 선택 처리, 로컬 저장을 한 프로젝트 안에서 다룬다.

## 구성과 의존 방향

- 씬의 `GameManager`는 Unity가 연결해 준 CSV를 `CardDatabase`에 넘기고, `GameSession`을 만들어 시작과 좌우 선택을 전달한다. 카드 선택을 프레임마다 확인하는 코드는 없다.
- `CardDatabase`는 CsvHelper로 CSV를 읽어 사건별 카드 변형을 조회한다. `CardSelector`는 세션에 다음 카드를 공급할 자리이며, 현재 구현은 항상 빈 결과를 반환한다.
- `GameSession`은 `GameState`에 스탯, 유산 플래그, 본 사건, 현재 카드를 반영한다. 저장은 `ISaveStore`를 호출하고, `SaveSystem`은 Newtonsoft.Json으로 로컬 파일을 읽고 쓴다.
- `Test.unity`의 `Test`는 `GameManager`를 끈 상태에서 임시 저장소를 가진 세션을 직접 호출한다. 스탯 표시와 좌우 버튼은 이 검증 씬에서 생성한다.
- `origin/JSW`의 스와이프 시제품은 입력과 카드 모션을 연결하고 자체 카드 공급기와 스탯 모델을 사용한다. 현재 `JMS` 작업 트리의 세션과 연결된 씬은 확인되지 않았다.

프론트가 만든 UI와 통합할 때는 화면에서 확정한 좌우 입력을 `GameManager`에 전달하고, UI는 세션에서 확정한 카드와 스탯을 표시한다. 선택 규칙과 진행 저장은 백엔드 세션에 둔다. Unity 씬 연결을 통해 같은 프로세스 안에서 호출한다.

## 선택 한 번의 흐름

현재 카드가 있는 세션에 좌우 선택을 전달하면, 세션이 해당 선택지의 효과와 사건 기록을 상태에 반영한다. 그다음 카드 선택기를 호출하고 카드 변경 알림을 낸 뒤 진행을 파일에 쓴다. 구현 예정인 계층 전환에서는 새 계층의 첫 카드와 체크포인트를 함께 저장한 뒤 카드 변경과 계층 전환을 차례로 알린다.

게임에서 상태가 넘어가는 경계는 Unity 씬 입력, CSV 콘텐츠, 기기의 로컬 저장 파일이다. 런타임에서 진행을 외부 서비스로 보내는 경로는 없다.
