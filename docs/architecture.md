# 게임 구성

동아리에서 만드는 Unity 2D 카드 게임이다. 현재 작업 브랜치인 `JMS`에서 계층별 사건 데이터, 선택 처리, 로컬 저장을 한 프로젝트 안에서 다룬다.

## 구성과 의존 방향

- 시작 씬의 `GameManager`는 새로하기나 이어하기 호출을 기다린다. 연결된 CSV를 `CardDatabase`에 넘기고 `GameSession`에 시작, 좌우 선택과 복원을 전달하며, UI에는 확정된 상태를 이벤트로 알린다.
- `CardDatabase`는 CsvHelper로 CSV를 읽고 행 순서를 유지하며 사건과 변형을 조회한다. `CardSelector`는 계층, 유산 조건, 사건 기록과 남은 턴을 받아 다음 카드만 고른다.
- `GameSession`은 `GameState`에 스탯, 유산 플래그, 본 사건, 현재 카드를 반영한다. 저장은 `ISaveStore`를 호출하고, `SaveSystem`은 Newtonsoft.Json으로 로컬 파일을 읽고 쓴다.
- `Test.unity`의 `Test`는 새로하기·이어하기 메뉴와 수동 화면을 연결한다. `TestDemoSession`은 `TestDemo/save.json`에서 수동 진행을 유지하고, `GameSessionChecks`는 임시 저장을 사용하는 별도 세션에서 자동 검사를 실행한다.
- `origin/JSW`의 스와이프 시제품은 입력과 카드 모션을 연결하고 자체 카드 공급기와 스탯 모델을 사용한다. 현재 `JMS` 작업 트리의 세션과 연결된 씬은 확인되지 않았다.

프론트가 만든 UI와 통합할 때는 화면에서 확정한 좌우 입력을 `GameManager`에 전달하고, UI는 세션에서 확정한 카드와 스탯을 표시한다. 선택 규칙과 진행 저장은 백엔드 세션에 둔다. Unity 씬 연결을 통해 같은 프로세스 안에서 호출한다.

## 선택 한 번의 흐름

좌우 선택을 전달하면 세션이 다음 진행을 임시 상태에 계산한다. 스탯이 한계에 도달한 경우에는 해당 계층의 진입 상태로 복귀한다. 계층이 바뀌는 경우에는 새 첫 카드와 체크포인트를 진행 상태에 함께 담는다. 저장에 성공하면 공개 상태를 갱신하고 카드 변경과 실제 계층 전환을 차례로 알린다.

게임에서 상태가 넘어가는 경계는 Unity 씬 입력, CSV 콘텐츠, 기기의 로컬 저장 파일이다. 런타임에서 진행을 외부 서비스로 보내는 경로는 없다.
