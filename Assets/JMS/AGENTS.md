# 카드 진행과 로컬 저장

`Scripts/`의 카드 데이터·세션·저장과 `Sources/events.csv`, `Scenes/Test.unity`를 담당한다. 프론트 담당자가 만든 UI에는 `GameManager`를 통해 좌우 선택과 결과 확인 지점을 제공한다. 카드 화면, 스와이프 연출, 레이아웃은 프론트 담당 범위다.

- 카드 대사와 변형은 CSV에서 읽는다. 다음 카드를 정할 때 계층과 유산 조건을 적용하고, 사건 ID로 이미 본 사건을 걸러낸다. 메인 사건 순서를 검증할 때는 같은 사건의 여러 변형을 한 건으로 센다.
- 좌우 입력은 `GameManager`가 세션에 전달한다. 스탯, 플래그, 본 사건과 현재 카드는 세션의 선택 처리에서 함께 갱신한다. 스와이프 확정과 애니메이션 종료가 따로 전달돼도 선택 효과가 한 번만 적용되도록 연결한다. 테스트에서 저장 경로를 바꿀 때는 `ISaveStore`를 사용한다.
- 체크포인트를 구현할 때는 첫 카드와 진입 당시 스탯·플래그를 보관한다. 실제 계층 전환 알림은 새 진행이 저장된 뒤 보낸다. 0 또는 100에 도달한 선택의 검증은 마지막 카드에서 발생하는 경우도 포함한다.
- `Test.unity`는 비활성화된 `GameManager`와 임시 세이브를 전제로 한다. 현재 어셈블리에 포함되는 `Test.cs`도 모델과 함께 컴파일되는지 확인한다.
- 새 진행 로직을 검증할 때는 0턴, 메인 카드 예약, 카드 조기 소진, 두 유산 변형, 게임 오버 복귀, 전환 이벤트 콜백 안에서의 저장 읽기를 확인한다.
